# PR #188 (LP-0023 rewrite): capability map

Read-only survey of the repository at `547f183` plus the changes in this branch. The requirement
rows are the new "IDL format and tooling" bullet of `logos-co/lambda-prize` PR #188
(`prizes/LP-0023.md`) and the SDK bullet it rewrites. Line numbers are READ against `547f183`
unless the row says "this branch".

| Required capability | What lezreg had at 547f183 | Gap / what this branch adds |
| --- | --- | --- |
| Generate a program's IDL from its **source** (messages in Borsh order with names/types/docs, actor state, events) | The registry's own v1 IDL is generated by the released `spel generate-idl` v0.7.0 over `program/src/lib.rs`; `scripts/idl.sh --check` regenerates it (FURPS §1, `scripts/idl.sh`). `tools/idl-drift/src/lib.rs:12-40` only *adds* `x-lez04` facts to that output. | **Still a gap:** this repo has no generator for SPEL IDL v2 / `lez-idl` from source. This branch publishes the registry's v2 IDL as a checked twin of v1, but does not generate it from source. |

## What is deliberately not claimed

- No chain, sequencer, proof, network, Mini or M2 was used; `--plan` is an offline plan, not a
  simulation. The registry's own simulated `--dry-run` remains the place that reports cycles,
  fees and apply/revert.
- The on-chain program and `artifacts/` are untouched, so the registry's image id does not change.
- The v2 file mirrors v1's field types verbatim (including `[u8; 32]` where v2 prefers
  `account_id`) so that both encode byte-identical messages; it is a presentation of the same
  interface, not an independently generated artifact.
- `spel` on branch `refactor/lez-v0.4.x` already has `encode`, `inspect --data`, `generate-idl`
  and `send --dry-run` (`docs/reference/cli.md` there). Where upstream tooling already covers a
  capability, this branch adds the same capability to lezreg rather than replacing it.
